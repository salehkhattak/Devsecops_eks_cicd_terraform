# Three-Tier Flask Application & DevSecOps EKS Project Summary

## Project Overview

This is a production-ready, three-tier Flask application with complete CI/CD pipeline,
Infrastructure as Code (IaC), and Kubernetes deployment manifests targeting AWS EKS.

---

## Architecture

### Presentation Tier (`frontend/`)
- Modern HTML/CSS/JS with Glassmorphism UI
- Asynchronous interactions via fetch API
- Real-time toast notifications and like buttons

### Application Tier (`backend/app/`)
- Flask REST API
- Layered architecture: routes.py → services.py → models.py
- Database migrations handled automatically via `init_db_schema()`

### Data Tier (MySQL 5.7)
- Auto-schema migration (adds author, likes, created_at columns)
- Health checks for container readiness

---

## Infrastructure as Code (IaC)

### `terraform-iac/`
| File | Purpose |
|------|---------|
| `main.tf` | Orchestrates VPC, EKS, and Load Balancer modules |
| `variables.tf` | Configurable defaults (region, instance type, node count) |
| `provider.tf` | AWS provider configuration |
| `output.tf` | Exports cluster details |
| `user-data.sh` | Node bootstrap script |

### `remote-infra/`
- S3 backend for remote `.tfstate` storage
- DynamoDB for state locking

---

## CI/CD Pipeline (Jenkins)

**File:** `Jenkinsfile`

```
Git Clone → OWASP Scan → SonarQube Analysis → Trivy FS Scan →
Docker Build → Trivy Image Scan → Push to DockerHub → K8s Deploy
```

### Shared Library Steps (`vars/`)
| Step | Function |
|------|----------|
| `sonarScan.groovy` | Static code analysis |
| `trivyScan.groovy` | Filesystem vulnerability scanning |
| `owaspScan.groovy` | Dependency vulnerability check |
| `docker_push.groovy` | Secure DockerHub push with credentials |
| `k8s_deploy.groovy` | Kubernetes deployment with sed image substitution |

## Kubernetes Manifests

### `myk8s/` (Local/Minikube)
- `app-deployment.yml` — Flask app with initContainer for MySQL readiness
- `app-svc.yml` — ClusterIP service
- `mysql-deployment.yml`, `mysql-svc.yml`, `mysql-pv.yml`, `mysql-pvc.yml`
- `namespace.yml`, `hpa.yml`

### `eks-manifests/` (Production AWS)
- `three-tier-app-deployment.yml` — AWS-optimized Flask deployment
- `three-tier-app-svc.yml` — LoadBalancer service
- `mysql-deployment.yml`, `mysql-svc.yml` — MySQL with Secrets/ConfigMap
- `mysql-secrets.yml` — Base64-encoded credentials
- `mysql-configmap.yml` — Init SQL script

## Security Features

1. **OWASP Dependency Check** — Scans for known vulnerabilities
2. **SonarQube** — Static code analysis and quality gates
3. **Trivy FS Scan** — Filesystem vulnerability scanning pre-build
4. **Trivy Image Scan** — Container image vulnerability scanning post-build
5. **Kubernetes Secrets** — Base64-encoded MySQL credentials
6. **Non-root Containers** — Application runs without root privileges
7. **Image Pull Policy: Always** — Ensures latest security patches

---

## Notable Bugs Fixed in This Project

1. **Service Name Mismatch** — `MYSQL_HOST` changed from `mysql-svc` to `mysql`
2. **Race Condition** — InitContainer added to wait for MySQL readiness
3. **MYSQL_HOST Default** — Kept as `'mysql'` for Docker compatibility

## Local Development

```bash
# Full stack
docker-compose up --build -d

# Access points
Flask App: http://localhost:5000
Jenkins:   http://localhost:8080
SonarQube: http://localhost:9000
Prometheus: http://localhost:9090
Grafana:    http://localhost:3000
```

---

## Production Deployment

```bash
# 1. Provision infrastructure
cd terraform-iac && terraform init && terraform apply

# 2. Apply Kubernetes manifests
kubectl apply -f eks-manifests/

# 3. Jenkins triggers deployment after security scans pass
```
